# winget packaging

`manifests/` mirrors the layout of [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs):
`manifests/d/Devigami/SS14AutoJoin/<version>/` holds the three manifest files for one release, generated by
`tools/make_winget_manifest.py <version> <sha256 of SS14AutoJoin-<version>-windows-x64.exe> [release date]`.

The package is `Devigami.SS14AutoJoin`, a *portable* installer: winget copies the window executable into its
portable folder and adds the alias `SS14AutoJoin` to the path. Installing this way avoids the SmartScreen
prompt, because the file never carries the browser's mark of the web.

## First submission (once, by hand)

1. Fork `microsoft/winget-pkgs`, copy `manifests/d/Devigami/SS14AutoJoin/1.0.0/` into the same path in the
   fork, and open a pull request. Optionally validate first on Windows with
   `winget validate --manifest manifests/d/Devigami/SS14AutoJoin/1.0.0` and
   `winget install --manifest manifests/d/Devigami/SS14AutoJoin/1.0.0`.
2. The winget bots check the URL, the hash and the schema; a moderator merges. Expect a few days.

## Later versions (automatic)

`release.yml` has a `winget` job that runs `vedantmgoyal9/winget-releaser` after each release. It needs a
repository secret `WINGET_TOKEN`: a classic personal access token with the `public_repo` scope belonging to an
account that has a fork of `winget-pkgs`. The job is skipped while the secret is absent. It reads the new
release's assets, computes the hash, and opens the update pull request in `winget-pkgs` itself.
